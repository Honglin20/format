# 子任务生命周期

每个子任务从开始到结束遵循固定节奏，**不得跳过任何步骤**。

## 5 步骤

### 步骤 1：实现 → TDD

先写失败测试 → 实现 → 测试通过。测试与实现在同一 commit。

### 步骤 2：Review

派遣 review agent，修复 Critical/Major 问题。Minor 可记录但不阻塞。

### 步骤 3：Commit

小步提交，测试 + 实现在同一 commit。Commit 格式见 `branching-commits.md`。

### 步骤 4：总结与状态更新

立即更新 `docs/status/CURRENT.md`：
- 打勾已完成子任务
- 更新"下一步"为具体的下一个子任务
- 更新"断点续传必读文件"（只列真正需要读的文件，≤5 个，带行号范围）
- 补充"关键经验记录"（跨任务复用的发现）

**不积累，不延后。**

### 步骤 5：子任务结束信号

完成上述步骤后，向用户说明：

> 子任务 X 已完成并提交。下一步是 Y。请按需 `/clear` 或开始新对话，以保持 context 干净。

- 用户决定何时执行 `/clear`
- 不应在同一 context 内连续推进多个子任务，除非用户明确要求
- CURRENT.md 是唯一持久化状态

## Context 管理

| 操作 | 执行者 | 时机 |
|------|--------|------|
| 子任务完成信号 | Claude | 每个子任务 commit 后 |
| `/clear` 清空 context | **用户** | Claude 发出信号后 |
| 新对话开始 | **用户** | 跨大子任务时 |
| Agent 代理读取 | Claude | 大量文件读取时 |
