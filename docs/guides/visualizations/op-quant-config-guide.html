🎯 Format 轴 — 数值格式

Format 决定每个数值用多少 bit、如何分配指数/尾数位。

IntegerIntFormat — 整数量化

符号-幅度表示 (ebits=0)。量化时需先归一化到 [-1,1] 再取整。int4 的 9 个量化级别：

-1.00 -0.75 -0.50 -0.25 0.00 0.25 0.50 0.75 1.00
格式bit量化级别数max_norm典型场景
int882571.75权重/激活默认
int4491.75权重压缩、W4A8
int2231.50极限压缩、研究
scheme = QuantScheme(format="int4")  # 默认 per_tensor
FloatFPFormat — 浮点量化 (MX sub-byte)

有指数位，动态范围大，不需要归一化。per_block 路径使用 MX 共享指数。

格式ebitsmbitsmax_norm特点
fp8_e4m345448MX 推荐格式，无 Inf/NaN
fp8_e5m25457344范围最大，有 Inf/NaN，适合梯度
fp6_e3m2346MX 6-bit 偏指数
fp4_e2m1236MX 4-bit，需 per_block 使用
scheme = QuantScheme.mxfp("fp8_e4m3", block_size=32)
StorageBFloat16 / Float16

用作 storage：所有量化点前先 cast 到存储精度。硬件原生支持。

cfg = OpQuantConfig(
    storage=QuantScheme(format="bfloat16"),
    weight=QuantScheme.per_channel("int4"),
)
LUTNF4Format (QLoRA)

4-bit 查找表格式，16 个非对称级别优化正态分布权重。零附近更密集。

scheme = QuantScheme.mxfp("nf4", block_size=64)

📏 Granularity 轴 — 量化粒度

Granularity 决定 scale 的共享范围。粒度越细，scale 越贴合局部值域，精度越高。

PER_TENSORPer-Tensor — 全张量共享一个 scale

最简单，但 outlier 拉高 scale，拖累正常值。POT 模式下 scale=2.0 (而非 2.41)。

int4 量化结果
0.00-1.000.500.00 2.500.001.50-0.50 0.000.50-1.500.50 1.00-0.500.00-0.50
scale = 2^round(log2(2.41)) = 2^1 = 2.0 → 归一化到 [-1,1] 后取 int4 → 反归一化 ×2.0

Channel 0 的值 (0.12, 0.33, 0.07) 归一化后全部 <0.25，量化为 0 或 0.25 — 浪费了 9 个级别中的 6 个。

scheme = QuantScheme.per_tensor("int4")
PER_CHANNELPer-Channel — 每 channel 独立 scale

每个输出 channel 各算一个 amax。解决了 outlier 问题，是权重量化的标准选择。

int4 量化结果
0.00-0.750.250.00 2.500.001.50-0.50 0.000.75-1.250.50 1.00-0.500.25-0.50
scale₀=0.85 | scale₁=2.41 | scale₂=1.28 | scale₃=0.98 — 每个 channel 用自己的 scale

Channel 0 用 scale=0.85，0.33 归一化后为 0.39 → 量化为 0.25 → 反归一化为 0.25。比 per_tensor 的 0.50 精确得多。

scheme = QuantScheme.per_channel("int4", axis=0)
PER_BLOCK (MX)Per-Block — MX 共享指数

沿指定轴切成 block_size 大小的块，每块共享一个 exponent。OCP MX 标准核心。

scheme = QuantScheme.mxfp("fp4_e2m1", block_size=32)
BANKPer-Bank — 银行粒度

沿 bank_axis 切成 bank_size 段，每段内所有元素共享一个 scale。是 SQ-format 的基础粒度。bank_size 必须整除对应维度。

from src.scheme.granularity import GranularitySpec, GranularityMode
# bank_size 必须整除 bank_axis 对应的维度
gran = GranularitySpec(mode=GranularityMode.BANK, bank_size=16, bank_axis=0)
scheme = QuantScheme(format="int4", granularity=gran)

🔄 Transform 轴 — 量化变换

Transform 在量化前/后对张量做变换，降低量化误差。正交于 Format 和 Granularity。

HadamardHadamardTransform — 正交旋转

量化前做 Fast Walsh-Hadamard Transform，将信息均匀分散。自逆变换：H(H(x)) = x。

问题：Outlier 集中

少数元素值很大，大部分值很小。scale 被拉高，小值精度丢失。

H(·)
解决：能量分散

Hadamard 旋转后值分布更均匀，量化更高效。inverse 恢复原域。

实测效果 (int4 per_channel)

+ Hadamard
0.13-0.880.380.13 2.50-0.501.50-0.50 0.000.75-1.250.50 0.88-0.630.13-0.38

MSE=0.0084 (vs 无 Hadamard 0.0083)。在此 4×4 小 tensor 上差异不大，但大模型上 Hadamard 通常带来显著 QSNR 提升。

from src.transform import HadamardTransform
scheme = QuantScheme(format="int4", granularity=GranularitySpec.per_channel(0), transform=HadamardTransform())
SmoothQuantSmoothQuantTransform — 激活平滑

将激活的量化难度迁移到权重：激活 ÷ s，权重 × s。乘法结果不变，但激活分布更平滑。

s_j = max(|X_j|)^α / max(|W_j|)^(1-α)    α=0.5 (默认)
forward(x) = x / s  |  inverse(x_q) = x_q (权重融合 W×s 补偿)
from src.transform import SmoothQuantTransform
sq = SmoothQuantTransform.from_calibration(X_act=act_stats, W=weight, alpha=0.5)
# 权重融合 (校准时一次性操作，之后权重用 IdentityTransform)
from src.transform.smooth_quant import fuse_smoothquant_weights
fused_model = fuse_smoothquant_weights(model, {"layer": sq})
PreScalePreScaleTransform — 可学习预缩放

量化前 ×scale，量化后 ÷scale。scale 可为 nn.Parameter (LSQ 学习) 或 buffer (校准写入)。

from src.transform import PreScaleTransform
scale = torch.nn.Parameter(torch.ones(128))
pre_scale = PreScaleTransform(scale, pot=True, channel_axis=-1)

🧮 GPTQ — Hessian 感知权重量化

GPTQ 是校准优化器 (不是 QuantScheme 的轴)，用 Hessian 信息逐列量化权重，补偿量化误差对后续列的影响。

CalibrationGPTQOptimizer 原理
朴素量化 (RTN)

每列独立量化。第 j 列的误差影响后续列输出，但不考虑。

GPTQ

量化第 j 列后，用 Hessian 将误差补偿到后续列。后续列"预吸收"误差。

参数默认值说明
block_size128每次 Hessian 更新处理的列数
damp_percent0.01Hessian 对角线阻尼 (防除零)
act_orderFalse按 Hessian 降序量化列 (高影响列先量化)
IdempotentGPTQ 幂等性 — _weight_scale

GPTQ 量化后写入 module._weight_scale buffer，forward 读取该 buffer 传入 quantize(w, scheme, scale=_weight_scale)，确保 re-quantization 幂等。

修复前: GPTQ 写入 FP32 权重 → forward 重新算 amax → re-quant 不幂等 → 精度下降
修复后: GPTQ 写入 _weight_scale buffer → forward 读 buffer → 幂等 → int4-pc QSNR 13.3→17.1 dB

GPTQ 通过 QuantConfig 使用 (正确 API)

# 方式 1: QuantConfig (推荐 — 高层 API)
from src.session._config import QuantConfig

cfg = QuantConfig(
    w_format="int4",
    w_granularity="per_channel",
    w_axis=0,
    gptq=True,                # 启用 GPTQ
    gptq_block_size=128,       # Hessian 更新块大小
    gptq_damp=0.01,            # 阻尼系数
    gptq_act_order=True,       # 按 Hessian 降序量化
)

🚀 Session — 完整使用流程

两种 API 风格：低层 OpQuantConfig (精细控制) 和高层 QuantConfig (字符串配置)。

方式 1: QuantConfig (推荐 — 字符串配置)

from src.session._config import QuantConfig
from src.session._session import run_quantization

cfg = QuantConfig(
    w_format="int4",
    w_granularity="per_channel",
    w_axis=0,
    a_format="int8",           # 激活格式 (None = 跟随 w_format)
    transform="hadamard",       # none | hadamard | smoothquant | prescale
    gptq=True,                   # 启用 GPTQ
    outlier_ratio=0.1,            # 10% outlier
    outlier_format="int8",        # outlier 用 int8
    scale_storage="pot",          # pot | fp32
    storage_bits=16,              # bfloat16 存储精度
)

qmodel, fp32_model, result = run_quantization(model, cfg, calib_data)

方式 2: OpQuantConfig (精细控制)

from src.scheme import QuantScheme, OpQuantConfig
from src.transform import HadamardTransform

cfg = OpQuantConfig(
    storage=QuantScheme.per_tensor("bfloat16"),
    weight=QuantScheme(
        format="int4",
        granularity=GranularitySpec.per_channel(0),
        transform=HadamardTransform(),
        outlier_format="int8",
    ),
    input=QuantScheme.per_tensor("int8"),
)

qmodel, fp32_model, result = run_quantization(model, cfg, calib_data)
